# Top companion and focus capsule

The approved mobile design uses one animated identity above the message viewport and one input surface below it. `ChatScreen` (an execution session) and private `ConversationChatScreen` (an aggregate conversation) use `TopChatCompanion` and the `FocusCapsuleComposer` variant of `SharedMessageComposer`.

- The scene stays clear of system bars and the back/action targets. IME and live tool state do not move it. The existing local side preference is kept within the top slot; accessibility exposes the same move action. Tap edits, 300 ms hold records a draft, upward release cancels; gestures remain mutually exclusive.
- A compact capsule opens directly into a full width native multiline field. The same `BasicTextField` stays mounted so selection/composition are not replaced with a second editor. Explicit keyboard dismissal or a message-area tap collapses the surface without clearing draft or attachments. A selector, attachment picker, recording, upload or background window borrows focus; returning restores editing. Recovery remains expanded after failed/unknown delivery.
- Text, attachments, revisions, voice destinations, receipt handling and submit locks remain owned by `ChatComposer` and `ChatStore`. The presentation object contains only edit/dismiss/overlay intents. An accepted submission collapses only its empty input; later draft edits are preserved. Unknown delivery is never automatically replayed.
- Expanded settings have three independent 48 dp targets. Session settings call the original store with rollback protection. Model selectors expose complete labels and search. Thinking options use reported model/provider capabilities; unknown capabilities retain the saved value and explain the missing information. Codex fixed permissions are explained rather than made editable. Permission changes display their current-session scope before confirmation.
- Aggregate private messages create independent work. Their three entries display the employee's actual first candidate and navigate, after an explanation, to existing employee defaults. Changes there affect subsequent new work; this UI has no per-message override and never writes a historical session as a proxy for the next message.
- Progress details use a sheet instead of stacking a large inline panel above the IME. Full tool output, approvals, errors, retry/reconcile and stop routes retain their original owners.
- `EmployeeAvatar(animated = true)` remains the only dynamic scene. Shared Web assets and fixed-identity mapping are read-only here. Reading/writing/thinking come from actual execution state, speaking from real playback. History and directory avatars use static rendering; group speakers retain identity.

`ChatPreviewActivity` is an opt-in, credential-free native fixture, not a real service session. Its receipt adapters are inert. Native regression covers focus borrowing, model search/select/cancel, picker return, text long press, tap/drag, ACK/error/unknown, attachments and fixed scene geometry. Preview screenshots and recordings must be labelled accordingly. User service permissions and physical-device acceptance require separate evidence.

### Composer surface hierarchy

Execution progress and queued-message recovery sit above the writing surface. They never enlarge its rounded background. The collapsed composer is one 48 dp toolbar; the add action, draft entry and visible send/stop actions share that surface. Only visible actions reserve width, while the expanded editor retains full width. Queue summaries retain a 48 dp touch target. iOS uses the same hierarchy.
