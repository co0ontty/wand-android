# Android 首页（工作台）重设计 · 2026-09-25

首页原来是一棵默认展开的目录树：每个目录行挂 `⌄ / 铅笔 / ＋ / ⋮` 四个图标，
每个任务行再挂 `⌄ / ＋ / ⋮`，每个会话行只有一个 8dp 状态点。信息量不小，
但读起来像「文件管理器 + 后台管理页」，不像一个客户端产品。这份文档记录重设计的
判断依据和落地规则，避免以后又慢慢漂回工具形态。

## 诊断：为什么像工具

| 现象 | 后果 |
| --- | --- |
| 每层标题都挂 3–4 个零散操作图标 | 视线被图标占满，页面像控制面板 |
| 会话只有一个小圆点表达状态 | 「在跑 / 在等我 / 空闲」要靠颜色猜 |
| 没有任何时间信息 | 无法判断「哪个是刚才那个」 |
| provider 只是标题下的一行灰字 | 没有品牌识别，列表缺少视觉锚点 |
| 「会话模式 ⌄」是个切换，却长得像下拉 | 模式语义不清，用户不敢点 |
| 主操作只有右上角一个 `＋` | 说不出「想干什么」就无从下手 |

对照同类产品的首页共识（Cursor for iOS、Claude Code mobile、Codex mobile、Devin）：

- **Cursor for iOS**：仓库列表 + 底部常驻的 prompt 输入条（选 repo / branch → 起 agent），
  仓库内是活动流，按时间分组并带结果标签和 diff 行数。
- **Claude Code mobile**：Code 页按项目分组的会话流；社区反复要的就是「分支 / 状态 /
  时间」这些区分性信息。
- **Codex mobile**：桌面侧栏已有未读圆点 + 相对时间，移动端缺这两个就被投诉。
- **Devin**：Agent Command Center 按状态分组，先回答「谁在跑、谁被卡住、谁等我验收」。

四条共同规则：**状态优先、时间可读、主操作常驻、管理动作收进菜单**。

## 落地规则

1. **三级文字层级**：工作区 15sp 半粗 → 任务 13sp 半粗·次级色 → 会话标题 14sp 正文。
   任务名是分组小标题，不允许和会话标题一样大。
2. **状态词汇出现在文字里**：运行中 / 等待授权 / 等待输入 / 已失败 / 已停止写成胶囊；
   「空闲」是常态，只留一个安静灰点，不写标签——让真正要看的跳出来。
3. **状态优先于结构**：顶部先给「N 个在跑 / N 个等你」，`等你` 可点开过滤成
   「只看需要处理的会话」；筛选后空目录、空任务会一起消失。
4. **管理动作收进菜单**：工作区头部只留 `⌄` 和 `⋮`（新建任务 / 审查 Worktree / 重命名），
   任务行同理。多选仍走长按。
5. **时间必须可读**：会话元信息行 = `形态 · 相对时间`（`结构化 · 12 分钟前`）。
6. **主操作常驻底部**：底部启动条是常驻输入框，回车把提示词带进「新建任务」面板
   （目录 / provider 仍在那里面确认）；左侧 `＋` 保留一键直达老路径。多选态下让位。
7. **空工作区不渲染空壳**：没有任务也没有会话的工作区收成一行紧凑条目，
   点它直接去建任务，而不是留一张点了没反应的卡片。

## 权限态为什么要单独喂进来

`GET /api/tasks` 的会话摘要里没有 `pendingEscalation`，所以首页原本看不到「等待授权」。
权限态只在 WS 事件里，因此复用已有的实时 overlay（`SessionTitleStore`，原来只存标题 /
ptyBusy）多存一位 `permissionBlocked`，由 `SessionWatcher`（WS 事件 + 会话列表刷新）和
`ChatStore` 写入。这样首页的「等你」是实时的，而且断线重连后会被列表刷新纠正。

## 代码位置

- `ui/screens/HomeChrome.kt`：顶部栏、分段控件、状态总览条、工作区卡片、会话行、底部启动条。
- `ui/screens/HomePresentation.kt`：纯函数（运行脉冲、需要处理过滤、相对时间、摘要分段），
  配套 `app/src/test/.../HomePresentationTest.kt`。
- `ui/screens/TaskListScreen.kt`：只做编排（弹窗、目录选择、批量操作），旧的树形渲染已删除。
- 宽屏侧栏不挂底部启动条（`showComposer = false`），主操作回到顶栏 `＋`。
